WiTV 频道菜单 · 半透明定稿 v2

同一画面：播放中打开频道菜单。两张都是 1920×1080 原稿（＝电视上 1280×720dp），衬底视频故意在面板底下放了一块高亮（最坏情况），用来看半透明下的可读性。

这一版只改一处：面板由实色改成半透明。其余设计元素逐条沿用各自方向的稿 ——「电视台包装」沿用 .impeccable/mocks/decision/grounded-broadcast.html（焦点行＝白色字幕条＋红色斜切号码块，正在播＝金色「直播中」，节目单按时间排、当前节目原位高亮带进度条）；「标准」沿用 .impeccable/mocks/decision/canon.html（深色面板，焦点行＝蓝色圆角块，正在播＝蓝点）。
半透明沿用实现里的分层，只把三栏拉齐：分组列 85%、频道列与节目单列 78%（现状是 88% / 75% / 88%，三栏深浅不一）。焦点行、当前节目块、正在播牌子保持实色不透明，可读性先由它们兜底。

半透明规格（两主题共用）

规则说明
只让面板半透明焦点行、当前节目块、正在播牌子保持实色——半透明一旦蔓延到这三处，主信息就会随视频花色浮动。
分栏靠线和底色实色面板时代靠底色深浅分栏；半透明后视频会盖过这点差异，所以节目单列补回稿里的竖线，分组列仍比频道列深一档。不靠提高不透明度来分栏。
最坏情况对比度（衬底纯白视频）频道列 78%——包装主文字 9.2:1、次要文字 5.5:1，标准主 8.9:1、次 5.3:1；分组列 85%——包装主 12.6:1、次 7.5:1。都过 WCAG AA（次要文字 ≥4.5:1 的门槛有富余），不用为了可读性再加遮罩或调高不透明度。
不做毛玻璃N1 这类盒子（Android 7.1、S905）没有便宜的高斯模糊（RenderEffect 要 API 31），半透明下要立住只能靠底色和字重。
字重上限 700稿里的 900（号码块、节目单台名、牌子）在 Android 上要打包一份中文 Black 字重才做得到，APK 会涨十几 MB，为上 F-Droid 不划算。定稿统一 700，层级改由字号与颜色承担。
面板右缘仍是硬边现状（面板与遮罩各占一半，接缝是一条硬竖线）。要软化得给遮罩加一段渐变，那是新元素，这一版没加。

与当前实现的差距（本版之后要补的）

  • 字重全是 400：item_channel_card.xml、item_channel_group_card.xml 里没有 textStyle，台名 / 号码 / 选中分组都要 700。
  • 号码位置反了：现在号码在行尾（18sp 次要色），稿是行首号码块；焦点行现在只在行首加一条 6dp 红条，稿是红底右缘斜切的号码块。
  • 正在播的标记：现在两套主题都是 18dp 绿色三角（ic_now_playing 里颜色写死 #4CAF50），稿是包装＝金色「直播中」牌、标准＝蓝点。
  • 节目单栏还是一个纯文本 TextView（当前播出 / 即将播出两行），要做成时间列 + 分隔线的节目列表，当前节目原位高亮（包装另带牌子与进度条）。
  • 三栏没有分栏线，节目单列左边那条要补。
  • 行圆角 6dp（稿：包装 8dp、标准 12dp）；标准的焦点行还带着白描边，稿里没有。
  • 提示文案是「确认：播放」，稿里是「确认 播放」。

这七条与半透明无关，是落地时被简化掉的部分；改法与影响面另外说明。
